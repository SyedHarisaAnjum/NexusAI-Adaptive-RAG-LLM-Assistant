# Deployment guide

This deploys the backend (Docker, with a persistent disk) and the frontend (static site) to [Render](https://render.com) using the `render.yaml` Blueprint.

**Cost:** the static frontend is free. The API needs a paid instance (Render *Starter*) because free instances have no persistent disk. Without a disk, uploaded documents and accounts would be lost on every deploy or restart.

## 1. Push the code to GitHub

```bash
git init
git add .
git commit -m "AI Q&A Assistant"
git branch -M main
git remote add origin https://github.com/<you>/ai-qa-assistant.git
git push -u origin main
```

Before pushing, check that `git status` does **not** list `.env`, `data/` or `backups/`. They are in `.gitignore`.

## 2. Create the services

1. In Render: **New → Blueprint**, then select the repository. Render reads `render.yaml` and proposes two services: `ai-qa-assistant-api` and `ai-qa-assistant-web`.
2. Fill in the values Render asks for:

| Service | Variable | Value |
|---|---|---|
| api | `GEMINI_API_KEY` | Your Gemini key — a **new key used only for this deployment** |
| api | `CORS_ORIGINS` | The frontend URL, e.g. `https://ai-qa-assistant-web.onrender.com` |
| api | `DEMO_USER_EMAIL` / `DEMO_USER_PASSWORD` | A throwaway demo login, e.g. `demo@example.com` / a random 16+ character password |
| web | `VITE_API_BASE_URL` | The API URL, e.g. `https://ai-qa-assistant-api.onrender.com` |
| web | `VITE_DEMO_EMAIL` / `VITE_DEMO_PASSWORD` | Same as the API's demo account (shows the "Try the demo account" button) |

`JWT_SECRET` is generated by Render automatically.

3. **Apply**. Service URLs are only known after the first deploy, so set `CORS_ORIGINS` and `VITE_API_BASE_URL` to the real URLs if they differ, then redeploy (the frontend must be rebuilt for `VITE_*` changes to take effect).

## 3. Check it

- `https://<api>/health` returns `{"status": "ok"}`.
- Open the frontend, click **Try the demo account**, upload a PDF and ask about it.
- The API service's **Logs** tab shows one JSON line per request.

## Protecting your Gemini quota and key

- The demo account is shared, so anyone can use your Gemini quota through it. The per-user rate limits cap this. Lower `RATE_LIMIT_CHAT_PER_MINUTE`, or set `ALLOW_REGISTRATION=false`, if needed.
- Set a usage or budget alert for the key in Google AI Studio / Google Cloud.
- If the key is ever exposed, revoke it in AI Studio and update `GEMINI_API_KEY` in Render.

## Backups and restore

- With `ENVIRONMENT=production` (set in the Dockerfile), the API writes `/data/backups/backup-<timestamp>.tar.gz` every `BACKUP_INTERVAL_HOURS` (default 24) and keeps the newest `BACKUP_KEEP` (default 7).
- Render also takes daily snapshots of persistent disks, so you can roll the disk back from the dashboard.
- To make a backup on demand: open the service **Shell** and run `python -m app.services.backup_service`.
- To restore a backup:
  1. Stop traffic (suspend the service, or scale to 0).
  2. In the Shell: `rm -rf /data/app/* && tar -xzf /data/backups/backup-<timestamp>.tar.gz -C /data/app`
  3. Restart the service.
- Backups on the same disk don't protect against losing that disk. For off-site copies, download them periodically or sync `/data/backups` to cloud storage.

## Other hosts

The image is a standard container. Any host that can run Docker with a persistent volume mounted at `/data` will work, for example Fly.io (volumes), Railway (volumes) or a VM with `docker compose`. Set the same environment variables. The frontend can go on any static host (Vercel, Netlify, Cloudflare Pages): use root `frontend`, build command `npm run build`, output `dist`, and the `VITE_*` variables.
